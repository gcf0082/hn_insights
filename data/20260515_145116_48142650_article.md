# Rust 语言 LLM 使用政策总结

## 基本信息

- **洞察链接**: https://github.com/rust-lang/rust-forge/pull/1040
- **标题**: Add an LLM policy for `rust-lang/rust`
- **作者**: jyn514
- **状态**: 开放 (Open)
- **创建时间**: 2026年4月17日

## 政策概述

该文档为 `rust-lang/rust` 仓库建立了一个关于如何在其贡献中使用 LLM（大语言模型）的政策。该政策不涵盖子仓库、子模块和 crates.io 依赖，也不适用于 rust-lang 组织下的其他仓库。

该政策计划发布在 Forge 上作为一份活文档，而非作为僵化的 RFC。它将从 rust-lang/rust 的 CONTRIBUTING.md 文件链接，并同时链接到 rustc-dev-guide 和 std-dev-guide。

## 政策背景与动机

### 为什么要制定此政策？

1. 许多人觉得阅读和审核 LLM 生成的代码和文字令人非常不舒服
2. 许多人认为 LLM 对学习和发现非常有帮助
3. rust-lang/rust 目前正面临大量低质量的"垃圾"PR，这些 PR 主要由 LLM 生成
4. 拥有明确的政策可以更轻松地进行审核，无需对每个案例逐一判断

### 审核准则

该 PR 之前的讨论已在 Zulip 上进行了大量讨论（超过 3000 条消息）。以下主题被明确标记为超出范围：

- LLM 的长期社会或经济影响
- LLM 的环境影响
- LLM 输出的版权状态
- 对使用 LLM 的人的道德评判

## 政策的主要内容

### 核心原则

政策采用"宁严勿宽"的原则，以便于理解和审核。

### 先例参考

该政策参考了多个开源项目的做法：

**完全禁止**：
- postmarketOS
- Zig
- Servo
- QEMU

**有监督的使用（人类最终负责）**：
- SciPy（严格的归属政策，包括模型名称）
- LLVM
- Blender
- Linux 内核
- Mesa
- Firefox
- Ghostty
- Fedora

**鼓励使用**：
- curl
- Linux Foundation

## 政策的局限性

1. **禁止了一些有效的 LLM 使用方式**：政策故意禁止多于允许，以确保易于理解和审核
2. **不解决道德、社会和环境影响**：这些话题在 Zulip 上广泛讨论但未达成共识
3. **不尝试建立项目级政策**：经过一个月的尝试未能达成共识
4. **不适用于 rust-lang/rust 的子树**：那里没有相同的审核问题

## 其他选择

政策制定者考虑了以下替代方案：

1. **项目级政策**：优点是统一，缺点是难以让所有人同意
2. **对项目内部人员和外部贡献者不同标准**：会强化现有权力结构
3. **更宽松的政策**：定义"负责任和适当"使用很困难
4. **更严格的政策（完全禁止）**：可能导致许多人离开项目
5. **移除"原创性门槛"条件**：使政策更容易审核，但可能迫使贡献者撒谎

## 结论

该政策是 Rust 项目在面对 LLM 生成内容日益增多的情况下的首次系统性尝试。它试图在允许 LLM 作为学习工具和防止低质量"垃圾"PR 之间取得平衡。政策的设计重点是易于理解和审核，而非涵盖所有可能的边缘情况。
