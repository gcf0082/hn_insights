## 项目概述

re_gent 是一款专为 AI 编码代理设计的版本控制系统。其核心理念是：虽然人类开发者使用 Git 管理代码，但 AI 代理缺乏属于自己的"版本控制"工具。re_gent 通过记录每个 AI 操作（工具调用）、关联提示词、追踪对话历史，为 AI 代理活动提供可审计的能力。

## 核心功能

### 已完成功能
- `rgt init` - 在当前目录初始化 `.regent/` 配置
- `rgt log` - 查看步骤历史（支持 `--session`、`-n`、`--since` 过滤）
- `rgt sessions` - 列出所有活动会话
- `rgt status` - 显示当前仓库状态
- `rgt show <step>` - 显示某个步骤的完整上下文
- `rgt blame <path>[:<line>]` - 查看文件的逐行来源信息
- `rgt cat <hash>` - 通过哈希值检查任意对象
- `rgt completion` - 生成 shell 补全脚本

### 即将推出
- `rgt rewind <step>` - 非破坏性时间旅行
- `rgt gc` - 垃圾回收
- `rgt fork <step>` - 从某个步骤创建新会话

## 技术架构

### 数据存储结构
```
.regent/
├── objects/     # 内容寻址存储 (BLAKE3哈希)
├── refs/        # 会话指针 (每个代理一个)
├── index.db     # SQLite 查询索引
└── config.toml
```

### 核心概念：Step (步骤)
每个工具调用创建一个步骤，包含：
- **parent**: 前一个步骤的哈希
- **tree**: 工作区快照
- **transcript**: 对话增量
- **cause**: 工具名称、参数、结果
- **session_id**: 会话标识符
- **timestamp**: 时间戳

### 设计优势
- **内容寻址存储** - BLAKE3 哈希，自动去重
- **快速查询** - SQLite 索引，查询时间 <10ms
- **每会话DAG** - 支持并发代理，无冲突
- **对话追踪** - 即使 `/compact` 或 `/clear` 也能存活
- **钩子驱动** - 透明集成 Claude Code

re_gent 是 Git 的补充，而非替代品。

## 应用场景

1. **审计追溯** - 当 AI 生成代码出现问题时，可追溯到具体是哪条提示词触发了该操作
2. **并发调试** - 多个 AI 会话可独立运行，通过独立分支追踪
3. **版本回滚** - 可非破坏性地恢复到任意之前步骤
4. **透明度提升** - 开发团队可清晰了解 AI 代理的所有变更
