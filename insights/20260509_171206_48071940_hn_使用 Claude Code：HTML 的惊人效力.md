## 内容摘要

这篇文章探讨了作者从 Markdown 转向 HTML 作为 Claude Code 输出格式的实践经验和理由。

### 核心观点

1. **HTML 更容易阅读**: 作者发现超过 100 行的 Markdown 文件很难阅读，而 HTML 文档在浏览器中更容易阅读和导航。

2. **交互性优势**: HTML 可以包含嵌入式图表、交互式组件、Mermaid 图表等，这是 Markdown 无法做到的。

3. **单一文件便利性**: 可以创建一个包含所有样式和 JavaScript 的单文件 HTML，易于分享和分发。

4. **视觉密度**: HTML 页面在浏览器中呈现时具有更好的视觉层次结构。

### 应用场景

- 设计文档和规格说明
- 技术文档
- 内部备忘录和决策记录
- 交互式原型和仪表板
- 代码审查辅助工具

## 社区讨论要点

### 支持观点

- **单文件 HTML 工具**: 开发者可以用单个 HTML 文件创建小型工具和应用，易于通过 LLM 协作修改。
- **交互式文档**: 可以嵌入交互式可视化、图表和动态内容。
- **分享便利**: HTML 文件可以通过浏览器直接打开，无需额外的渲染工具。
- **结构化格式优势**: 相比 Markdown，HTML/JSON 等结构化格式更适合静态分析和验证。

### 争议和质疑

- **编辑困难**: 有评论者认为 HTML 难以手动编辑，不如 Markdown 适合人类协作者。
- **Token 效率**: HTML 相比 Markdown 需要更多 token，可能增加使用成本。
- **编辑工具支持**: 一些用户指出现代编辑器和 VS Code 插件已经支持 Markdown 预览。
- **实用性争议**: 有评论认为"难以阅读超过 100 行的 Markdown"是技能问题而非工具问题。

### 其他观点

- 有人提到可以结合使用 Markdown 和 HTML（如嵌入 HTML 于 Markdown 中）。
- 有人建议使用 Typst 处理 Markdown 生成更美观的文档。
- 有人认为这是 Anthropic 推动增加 token 使用的策略。

## 总结

这篇文章反映了 AI 辅助编程工具在文档输出格式方面的新趋势。虽然 HTML 确实提供了更多的交互性和视觉表达能力，但也引发了关于编辑便利性和资源消耗的讨论。社区反馈显示出对不同工具偏好的多样性，没有统一的最佳解决方案。
