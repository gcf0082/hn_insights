## 政策概述

Rust 团队为 `rust-lang/rust` 仓库制定了 LLM（大型语言模型）使用政策，旨在规范 AI 工具在编译器贡献中的使用。该政策的主要内容包括：

### 允许的行为
- 向 LLM 提问关于现有代码库的问题
- 使用 LLM 总结 issues、PRs 或 RFC 上的评论

### 禁止的行为
- 禁止生成原创性代码贡献（需要达到"原创性阈值"）
- 禁止使用 LLM 进行代码审查

### 政策动机
1. 许多人觉得 LLM 生成的代码和文字令人不悦
2. 许多人认为 LLM 对学习和发现有很大帮助
3. Rust 编译器目前正面临大量低质量的"slop" PR（主要由 LLM 生成）
4. 有了明确政策可以更轻松地进行审核，无需逐个案例处理

## 社区反应

### 质疑观点

**用户 mw888**：批评 Rust 社区"过度保护"的做法，认为明确允许一些行为没有实际意义，因为无法验证是否遵守。"Linux 的政策更明智"。

**用户 7e**：预测 Rust 将出现"亲 LLM"的分叉，认为如果分叉使用 AI 进行代码审查，主流 Rust 将很快变得无关紧要。

**用户 voxl**：批评"LLM 狂热"令人无法忍受，反问如果 LLM 能在对数时间内显著改进编程语言，为什么没人做到。

### 支持观点

**用户 vintermann**：表示希望大学课程也有类似政策，因为曾经需要对使用 LLM 采取非常谨慎的态度。

### 其他观点

## 与其他项目的对比

该政策还引用了其他开源项目的 LLM 政策作为参考：

| 态度 | 项目 |
|------|------|
| **完全禁止** | postmarketOS、Zig、Servo、QEMU |
| **有条件允许** | LLVM、Linux内核、Mesa、Blender、Firefox、Fedora |
| **鼓励使用** | Linux Foundation、curl |
| **进行中** | NixOS |

Rust 的政策处于"禁止生成性使用，但允许非生成性辅助"的中间地带。

---

## 总结

Rust 团队的 LLM 政策反映了开源社区在 AI 工具使用上的典型困境：

1. **平衡的艺术**：政策试图在"完全禁止"和"完全开放"之间找到平衡点
2. **实用性考量**：政策明确指出是为了更易于审核，而非道德判断
3. **社区分裂**：对 LLM 的态度确实存在明显分歧，有人甚至预言会出现"反主流"的 Rust 分叉
4. **先例参考**：Linux 内核的政策被认为是更务实的参考

该政策的长期影响仍有待观察，但它代表了主流编程语言项目对 AI 辅助开发的态度转变。
