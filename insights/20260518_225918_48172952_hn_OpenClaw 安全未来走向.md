## 核心洞察

OpenClaw 是一个强大的 AI 个人助手，能够读取文件、运行命令、安装插件、访问网络并在真实机器上为真实用户执行操作。本文阐述了 OpenClaw 在安全方面的具体发展方向，体现了"强大但不意味着盲目、无限制或无法审计"的理念。

## 关键安全措施

### 1. 文件系统边界与 fs-safe

OpenClaw 在用户机器上运行，可以访问文档、代码库和照片。传统的路径遍历风险只是更大类别中的一个症状：不清晰的边界。fs-safe 是一套安全的文件系统模式，将根目录绑定保护封装成共享库，供核心代码、插件和相邻服务使用。这不是沙箱，而是防止文件系统代码中的边界穿越错误。

**下一步计划**: 将这些原语作为 ClawHub 上插件的预期模式，使绕过这些检查成为安全相关的信号。

### 2. 网络出口与 Proxyline

在 Agent 系统中，SSRF（服务器端请求伪造）比传统 Web 服务更难处理。用户控制或模型影响的 URL 是正常的产品行为。

OpenClaw 采用Proxyline 作为 Node 进程的路由层，安装进程级路由来控制 Node 网络表面，流量通过配置的代理发送。验证 URL 是不够的，因为验证时解析 DNS，获取时再次解析，答案可能在这两者之间改变。控制点从"包装器记得验证这个 URL"移到"出口流经代理策略"是更好的形态。

### 3. ClawHub 插件信任

ClawHub 是插件信任和来源的权威机构，提供多信号混合审查：ClawScan、VirusTotal、静态分析、元数据检查、来源追溯和人工审核。ClawHub 可以为特定包版本附加信任证据，标记为干净、可疑、隔离、撤销或恶意。

**关键原则**: 如果 ClawHub 标记某个版本为恶意并隔离，安装路径应拒绝下载。

### 4. 命令审批与提示疲劳

用户面临的现实是：提示来得太快无人能读，几分钟后用户会开启 YOLO 模式继续工作。解决方案是更少的提示和更好的提示。

- **解析改进**: 字符串匹配不够，策略需要理解嵌套的命令链。例如 `bash -c "rm -rf ~/something"` 中的 `rm` 应该被识别。
- **上下文审批**: 目标是让提示有意义——当提示出现时，用户应该停下来阅读。
- **Auto Review**: 对于 OpenAI 用户，暴露 Auto Review 功能，用独立的审查代理替代手动审批。

### 5. 静态分析

OpenClaw 收到了很多 GitHub 安全公告（GHSA）。修复公告后，使用 OpenGrep 进行精确规则检查，每个规则与公告、报告或审查发现关联。目标是回归检测和变体检测。

**当前状态**: 精确的 OpenGrep 规则包包含 148 条规则，在 PR 差异上运行。

## 总结

OpenClaw 不会变得不那么强大，而是在保持强大能力的同时，让边界更容易看到和防御。安全策略的核心承诺是：OpenClaw 可以保持强大，同时变得更加可防御。这不是承诺无风险的代理，而是展示明确的改进方向。
