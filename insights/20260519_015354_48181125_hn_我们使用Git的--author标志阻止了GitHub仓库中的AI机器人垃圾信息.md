## 文章摘要

本文来自 Archestra.AI 的 CTO Ildar Iskhakov,讲述了他们如何应对 GitHub 仓库中的 AI 机器人垃圾内容问题。

**核心问题:**
- 一个带有 $900 赏金的 issue 收到了 253 条评论,其中大部分是 AI 机器人产生的无意义"实施方案计划"
- 单单为 x.ai provider 支持这一个 issue 就收到了 27 个 Pull Request,大多数贡献者甚至没有尝试测试
- 团队成员每周需要花费半天时间清理 AI 垃圾内容
- 真正的贡献者被噪音淹没,无法获得关注

**解决方案:**
- 启用 GitHub 的"仅限 prior contributors"设置
- 使用 Git 的 `--author` 标志,为通过 CAPTCHA 验证的用户创建归因提交
- 构建了一套完整的入职流程:网站注册 → CAPTCHA 验证 → GitHub Action 自动创建归因提交 → 获得贡献者权限

**成效:**
- 第一周就成功阻止了约 500 个机器人

## 社区讨论要点

### 1. 解决方案的局限性
- **ELO 评分系统**:有用户建议使用 ELO 评分来评估贡献者质量,但立即遭到反驳:ELO 极易被操纵,而且 AI 可以轻易获得初始高分后开始提升其他 AI
- **信任圈模式**:部分用户认为"信任圈"可能比 ELO 更好,但需要考虑如何避免社区垄断和裙带关系

### 2. GitHub 本身的问题
- 有人指出 GitHub 的"首次贡献者免审批"设置存在安全漏洞:恶意用户可以通过一个微小的 typo 修改获得信任,然后提交恶意代码
- GitHub 没有任何动力去解决这个问题,因为他们正在积极推广 Copilot 和 AI 贡献

### 3. 替代方案讨论
- **付费保证金**:有用户提出收取 $10 保证金来提交 PR,但立即遭到反驳:这会让开源贡献变成付费劳动,并且会阻止发展中国家的开发者
- **PR 代币系统**:类似游戏中的邀请码机制,需要获得社区成员的" vouching"才能贡献

### 4. 对开源生态的影响
- 赏金任务和面试练习题可能需要重新考虑,因为它们容易成为 AI 垃圾的目标
- 有人提到 LiteLLM 仓库曾遭遇攻击者利用 AI 机器人试图操纵对话的安全事件

### 5. 关于"AI slop"的哲学思考
- 有评论指出,问题的根源在于整个行业都在宣传"AI 非常擅长写代码",导致很多人盲目相信 AI 可以完美完成任务
- StackExchange 模式存在的问题:社区门槛高,新人难以融入,存在"moderator cliques"

## 技术实现细节

1. **查找用户 GitHub ID**:
   ```bash
   gh api users/their-username --jq '.id'
   ```

2. **创建归因提交**:
   ```bash
   git commit \
     --author="their-username <ID+their-username@users.noreply.github.com>" \
     -m "chore: add their-username to external contributors"
   ```

3. **工作流程**:
   - 用户在网站完成入职流程(包括 CAPTCHA)
   - GitHub Action 自动获取用户 ID
   - 将用户添加到 EXTERNAL_CONTRIBUTORS.md 文件
   - 推送归因提交到 main 分支
   - 用户自动获得参与资格

## 洞察总结

这篇文章揭示了 AI 时代开源项目面临的新挑战:

1. **数量 vs 质量**:GitHub 报告的"增长"数据大部分是 AI 生成的垃圾内容,反而降低了真正的贡献质量
2. **猫鼠游戏**:简单的防护措施(如 CAPTCHA)只能提供短期保护,AI 必然会学会绕过
3. **生态平衡**:完全封闭会伤害合法的贡献者,完全开放则会被 AI 垃圾淹没
4. **平台责任**:GitHub 作为平台提供者,没有动机主动解决这个问题的

这是一个复杂的系统性问题,目前没有完美的解决方案,需要开源社区、平台提供者和 AI 开发者共同努力。
