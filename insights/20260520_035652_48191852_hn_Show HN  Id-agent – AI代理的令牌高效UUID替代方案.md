## 项目介绍

**id-agent** 是一个专为 AI 代理设计的新型 ID 生成库，旨在解决传统 UUID 在 AI 应用场景中的痛点。该项目将 UUID 替换为基于单词的可读性 ID，在 token 效率和防幻觉方面具有显著优势。

## 核心特性

### 1. Token 高效

- UUID v4 约消耗 23 个 token
- id-agent 默认配置（8 个单词）仅消耗约 14 个 token
- 可节省约 39% 的 token 成本

### 2. 人类可读

- 基于 4096 个精心挑选的英语单词
- 每个单词在 o200k_base 分词器中恰好为 1 个 BPE token
- 示例：`urd-antes-sorry-pac-dire-total-expire-going`

### 3. 防幻觉

- LLMs 经常产生虚构的 UUID
- id-agent 生成的单词型 ID 更易被 AI 正确记忆和识别

### 4. 可配置熵

- 支持 1-16 个单词，对应 12-192  bits 熵
- 默认 8 单词提供约 96 bits 熵，安全性相当于 300 万亿级别

## API 概览

```javascript
import { idAgent } from 'id-agent'

// 生成随机 ID
idAgent() // => "urd-antes-sorry-pac-dire-total-expire-going"

// 带类型前缀
idAgent({ prefix: 'task' }) // => "task_slide-exact-cede-bury-linge-ease-bean-impact"

// 从字符串生成确定性 ID
idAgent.from('user@example.com')

// 验证 ID
validate('storm-delta-stone')

// 创建别名映射（用于 LLM 上下文中的 token 压缩）
createAliasMap({ words: 3 })
```

## 社区反馈

### 质疑观点

部分开发者质疑该工具的必要性：
> "为什么生成 UUID 会有成本？LLM 可以在客户端生成 UUID，不消耗任何 token。"

### 积极反馈

有用户表示：
> "这确实解决了 LLMs 返回不存在 UUID 的问题。如果能显著减少幻觉，那将非常有用。"

### 核心争议

社区讨论的核心问题是：在实际 AI 应用中，token 成本和幻觉问题是否真的严重到需要专门的 ID 库来解决。

## 技术分析

### 优势

1. **Tokenizer 优化**：词表经过精心设计，每个单词恰好为 1 个 token
2. **安全性**：默认配置提供足够的熵，碰撞概率极低
3. **Zod 验证**：所有公共 API 都包含输入验证

### 局限

1. 主要针对 LLM 场景，通用性有限
2. 需要维护词表，可能需要定期更新
3. 在传统数据库场景中优势不明显

## 总结

id-agent 是一个针对 AI 代理场景的创新解决方案，通过单词型 ID 减少 token 消耗并降低 LLM 幻觉风险。虽然质疑声存在，但对于需要频繁与 LLM 交互的应用来说，该工具具有一定实用价值。
