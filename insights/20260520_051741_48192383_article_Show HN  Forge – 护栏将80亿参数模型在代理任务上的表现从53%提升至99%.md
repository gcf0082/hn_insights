## 项目概述

Forge 是一个专为自托管 LLM 设计的可靠性层，专门用于处理工具调用和多步骤代理工作流。该框架通过 Guardrails（保护机制）和上下文管理技术，将一个 8B 参数的本地模型提升到同类模型的顶级水平。

当前最佳自托管配置（Ministral-3 8B Instruct Q8 on llama-server）在 Forge 的 26 场景评估套件中达到了 86.5% 的得分，在最具挑战性的层级中达到了 76%。

## 核心特性

### 三种使用方式

1. **WorkflowRunner** — 定义工具、选择后端、运行结构化代理循环。Forge 管理完整生命周期：系统提示、工具执行、上下文压缩和保护机制。SlotWorker 提供优先队列访问共享推理槽位，适用于多代理架构。

2. **Guardrails 中间件** — 在您自己的编排循环中使用 Forge 的可靠性堆栈。您控制循环；Forge 验证响应、救援格式错误的工具调用、强制执行必需步骤。

3. **代理服务器** — 即插即用的 OpenAI 兼容代理，放置在客户端和本地模型服务器之间。透明地应用保护机制。

### 支持的后端

| 后端 | 最佳场景 | 原生函数调用 |
|------|----------|--------------|
| Ollama | 最易设置，内置模型管理 | 是 |
| llama-server | 最佳性能，完全控制 | 是（需 --jinja） |
| Llamafile | 单二进制文件，零依赖 | 否（提示注入） |
| Anthropic | 前沿基线，混合工作流 | 是 |

### 关键技术

- **Rescue Parsing**: 救援格式错误的工具调用
- **Retry Nudges**: 重试引导
- **Step Enforcement**: 步骤强制执行
- **VRAM-aware budgets**: VRAM 感知预算
- **Tiered compaction**: 分层压缩

## 安装方法

```bash
pip install forge-guardrails                # 仅核心
pip install "forge-guardrails[anthropic]"   # + Anthropic 客户端
```

开发安装：
```bash
git clone https://github.com/antoinezambelli/forge.git
cd forge
pip install -e ".[dev]"
```

## 项目结构

```
src/forge/
  core/           # 核心组件（消息、工作流、推理、运行器）
  guardrails/     # 保护机制（验证、步骤强制、错误跟踪）
  clients/        # LLM 客户端（Ollama、llamafile、Anthropic）
  context/        # 上下文管理（策略、硬件检测）
  prompts/        # 提示模板
  tools/          # 工具（合成响应工具）
  proxy/          # 代理服务器
tests/
  unit/           # 865 个确定性测试
  eval/           # 评估工具
```
