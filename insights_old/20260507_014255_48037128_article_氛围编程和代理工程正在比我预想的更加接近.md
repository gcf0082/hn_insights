## 核心观点

Simon Willison 在与 Joseph Ruscio 讨论 AI 编码工具时，意识到一个令人不安的现象：**vibe coding（氛围编程）和 agentic engineering（代理工程）之间的界限正在变得模糊**。

### 曾经清晰的界限

- **Vibe Coding**: 不看代码的编程方式，用户可能不是程序员，只关心结果是否可用，不关心代码质量。适合个人工具，出错只影响自己。
- **Agentic Engineering**: 专业软件工程师使用AI工具，需要理解安全、可维护性、性能等，以构建高质量生产系统。

### 现在的问题

随着编码代理工具越来越可靠，Simon 发现自己在生产级项目中也**不再审查每一行代码**：

> "如果让 Claude Code 构建一个 JSON API 端点来运行 SQL 查询并输出结果，它肯定能做对。你让它添加自动化测试和文档，你知道它会做得好。但我不再审查那代码了。我有一种愧疚感：如果我没有审查代码，在生产环境中使用它真的负责任吗？"

### 新的责任观

Simon 借用以前在大型组织中担任工程经理的经历：当其他团队交付一个服务时，他不会逐行阅读代码，而是信任该团队的专业声誉。但 AI 代理没有专业声誉来承担责任——尽管它不断证明自己的能力。

## 新挑战：评估软件

现在的困境是：
- 过去看到有100次提交、良好README和自动化测试的GitHub仓库，可以确定作者投入了大量心血
- 现在可以在半小时内创建一个有100次提交、漂亮README和全面测试的仓库！
- **外表看起来一模一样，但内在质量无法单从外观判断**

Simon 意识到：**相比于测试和文档的质量，更看重的是有人真正使用过这个工具**。如果一个 vibe coding 的东西被每天使用两周，比刚生成出来但几乎没使用的东西更有价值。

## 瓶颈已转移

- 从每天200行代码提升到2000行，会导致整个软件开发生命周期出现问题
- 上游设计流程也需要改变：因为设计修改的成本大幅降低，设计过程可以更冒险

## 为什么不为职业生涯担忧

1. 与 AI 代理对话对绝大多数人来说仍是"外星语言"
2. AI 工具是现有经验的放大器，如果你知道自己在做什么，可以跑得更快
3. 生产软件本身就是一件极其困难的事情
4. 引用 Matthew Yglesias 的观点："我不想 vibe coding —— 我想让专业管理的软件公司使用 AI 编码辅助来制造更多/更好/更便宜的软件产品"

## 对SaaS提供商的影响

企业客户需要的不是"自己动手"的解决方案，而是：
- 至少其他两个大型企业成功使用过该CRM六个月
- 需要经过验证的解决方案才愿意承担风险

## 总结

Simon Willison 揭示了 AI 编码工具发展中的一个核心张力：随着工具越来越可靠，我们是否应该放松对代码的审查？这涉及到软件工程的根本责任问题。虽然 vibe coding 和 agentic engineering 正在融合���但开发者需要意识到这种融合带来的责任风险——尤其是在构建他人依赖的生产系统时。
