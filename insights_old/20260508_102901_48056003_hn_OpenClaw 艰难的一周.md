## 洞察摘要

### 事件背景

OpenClaw 是一个基于 Claude 模型的 AI 自动化代理框架,近期被 Anthropic 公司停止 API 供应,导致大量依赖该服务的用户陷入困境。

### 用户实际用例

用户在讨论中分享了 OpenClaw 的多样化应用场景:

1. **智能家居控制**: 门铃、恒温器、能源监控、灯光控制
2. **自动化节能**: 检测离家时间自动调节恒温器,离开时关闭热水器
3. **工作通讯处理**: 监控工作聊天和邮件,自动处理并推荐后续行动
4. **购车搜索**: 按特定需求(6座、拖曳5000磅、CarPlay、加热座椅等)监控汽车网站
5. **日程规划**: 根据是否有孩子来规划每日活动,推荐新闻和阅读内容
6. **个性化推荐**: 推荐书籍、播放音乐,根据用户偏好调整

### 用户反馈与困境

- **怀念 Anthropic 提供的体验**: 用户表示其他可用模型完全无法企及
- **寻找替代方案困难**: 本地运行的模型性能不足,公司GPU又不适合
- **发现临时解决方案**: 可使用 `claude -p "prompt"` 直接调用 Claude CLI 执行单一任务
- **对AI泡沫的担忧**: 有用户批评这些用例"毫无价值",认为AI热潮存在泡沫

### 技术反思

- **"随机软件"概念**: 有评论提出需要为"随机软件"(stochastic software)建立新的心理模型
- **npm依赖安全隐患**: 批评安装过程引入大量未审查的npm依赖,存在供应链攻击风险
- **编码vs软件工程**: "编码"虽已解决,但"软件工程"仍面临挑战

## 结论

OpenClaw 用户群体虽小但活跃,此次事件暴露出对单一服务提供商的依赖风险。用户实际用例涵盖智能家居、个人生产力、工作自动化等领域,但许多人承认这些功能用简单脚本也能实现,AI模型只是增加了灵活性。社区正在探索使用 Claude CLI 等替代方案,但短期内难以重现原有体验。
