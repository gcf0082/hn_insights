# Firefox 安全加固洞察报告

## 基本信息

- **洞察链接**：https://hacks.mozilla.org/2026/05/behind-the-scenes-hardening-firefox/
- **发布时间**：2026年5月7日
- **作者**：Brian Grinstead、Christian Holler、Frederik Braun
- **分类**：Featured Article、Firefox、Security

## 报告摘要

Mozilla 宣布通过 Claude Mythos Preview 等 AI 模型识别并修复了 Firefox 中空前数量的潜在安全漏洞。本文深入介绍了 Mozilla 如何利用 AI 技术进行安全加固，包括发现的部分漏洞案例、加固管道的构建过程，以及对其他软件项目的建议。

## 核心发现

### 漏洞发现成果

Mozilla 在 Firefox 150 版本中通过 Claude Mythos Preview 发现了 **271 个漏洞**，这些漏洞分布在多个浏览器子系统中。其中包括多个沙箱逃逸漏洞，这类漏洞需要与其他漏洞结合才能实现完整的 Firefox 攻击链。

### 部分典型漏洞案例

| Bug ID | 漏洞描述 |
|--------|----------|
| 2024918 | JIT 编译器中的错误平等检查导致 WebAssembly GC 结构初始化被优化掉，产生可进行任意读写操作的伪造对象原语 |
| 2024437 | 存在于 `<legend>` 元素中长达 15 年的漏洞，通过跨浏览器远端部分的边界情况精心编排触发 |
| 2021894 | 通过 IPC 的竞态条件可靠利用，允许被攻陷的内容进程操作 IndexedDB 引用计数以触发 UAF 并可能实现沙箱逃逸 |
| 2022034 | 原始 NaN 跨越 IPC 边界时可伪装为带标签的 JS 对象指针，将双精度反序列化转变为父进程的伪造对象原语用于沙箱逃逸 |
| 2024653 | 复杂测试用例穿越嵌套事件循环、pagehide 监听器和垃圾回收，在 `<object>` 元素的属性 setter 中触发 UAF |
| 2025977 | 存在 20 年之久的 XSLT 漏洞，递归的 key() 调用导致哈希表重哈希，在原始条目指针仍在使用时释放其后备存储 |
| 2029813 | 通过利用 RLBox 沙箱验证逻辑中的间隙，逃逸针对第三方库的内置沙箱技术 |

### 漏洞严重程度分布

在 271 个漏洞中：
- **sec-high**：180 个
- **sec-moderate**：80 个
- **sec-low**：11 个

值得注意的是，并非每个 high 或 critical 级别的漏洞都能实际利用 Firefox。Firefox 采用纵深防御架构，例如利用 JIT 漏洞仅能在沙箱进程中获得远程代码执行，真实攻击通常需要将多个漏洞链接起来才能实现权限提升。

## AI 加固管道

### 技术背景

几个月前，AI 生成的安全漏洞报告大多被视为无用的「垃圾」。处理那些看起来合理但实际错误的报告会给项目维护者带来不对称的成本：使用 LLM 轻松找到代码中的「问题」，但回应这些报告却缓慢且昂贵。

这一情况在短短几个月内发生了根本性变化，原因包括两个主要因素：模型能力大幅提升；显著改进了利用这些模型的技术——引导、扩展和叠加模型以产生大量信号并过滤噪音。

### 管道构建

Mozilla 在早期实验中使用了 GPT-4 或 Sonnet 3.5 等模型进行静态分析，但高误报率使其难以规模化。后来引入的代理型 harness 可以可靠地检测安全问题，既能发现真实漏洞，又能驳回不可复现的推测。

关键在于：给定正确的接口和指令，harness 可以创建和运行可复现的测试用例，动态验证代码中关于漏洞的假设。在修复了 Anthropic 二月份发送的初始问题后，Mozilla 在现有模糊测试基础设施之上构建了自己的 harness。

### 扩展策略

从小规模实验开始，使用 Claude Opus 4.6 引导 harness 寻找沙箱逃逸漏洞。首先在终端中监督流程，观察实时过程并调整提示和逻辑。验证成功后，将任务并行化到多个临时虚拟机，每个虚拟机负责在特定目标文件中寻找漏洞并将发现写回存储桶。

发现子系统是必要但不充分的。为了扩展工作，需要将其与完整的安全漏洞生命周期集成：确定要查找什么、在哪里查找，以及如何处理结果。后者包括与已知问题去重、跟踪漏洞、分类处理和发布修复。

## 模型升级与效果

管道就绪后，切换不同模型变得轻而易举。提前构建此管道帮助 Mozilla 使用公开可用的模型发现了许多严重漏洞，也在有机会评估 Claude Mythos Preview 时立即投入运行。

在 Firefox 150 中修复了由 Claude Mythos Preview 识别的 271 个漏洞，还在 149.0.2、150.0.1 和 150.0.2 中发布了更多修复。2026 年 4 月总共修复了 423 个安全漏洞，超过 100 人为此次工作贡献了代码。

## 防御成果

模型未发现的漏洞同样值得关注。例如，近年来Mozilla收到了多份来自安全研究员的报告，他们试图通过在特权父进程中触发原型污染来逃逸进程沙箱。Mozilla 采取了架构层面的修复——默认冻结这些原型。在 harness 的审计日志中，可以看到许多尝试这条逃逸路径的尝试被这一设计阻止。这种直接回报比发现和修复更多漏洞更令人欣慰。

## 总结与建议

### 主要经验

- 任何构建软件的人都可以立即开始使用现代模型的 harness 来发现漏洞并加固代码
- 建议现在就开始，可以从非常简单的提示开始，然后观察和迭代
- 初始提示与公开描述的方法差异不大，但通过迭代构建了大量编排和工具来优化和扩展管道
- 核心循环本质不变：代码这部分有漏洞，请找到它并构建测试用例

### 未来计划

目前扫描主要集中在代码的特定区域（文件、函数），基于人工判断和自动信号的混合指导。未来计划将此分析集成到持续集成系统中，在补丁进入代码库时进行扫描。模型对提供的上下文形式非常灵活，预期基于补丁的扫描效果至少与基于文件的扫描一样好，甚至更好。

当前时刻既是危险的也是充满机遇的，让我们共同努力保护互联网安全。
