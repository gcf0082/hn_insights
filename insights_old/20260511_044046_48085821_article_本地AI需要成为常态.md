## 核心观点

作者批评了当前软件开发中的一个趋势：开发者动不动就调用 OpenAI 或 Anthropic 的 API 来实现 AI 功能。这种做法虽然方便，但带来了严重问题：

1. **脆弱性**：应用在服务器宕机或信用卡过期时立即失效
2. **隐私侵犯**：将用户内容发送到第三方 AI 提供商，带来了数据保留、合规、审计等大量问题
3. **架构复杂化**：把一个 UX 功能变成了一个**需要花钱维护的分布式系统**

作者认为，我们应当回归到让本地设备完成工作的习惯。口袋里的芯片比十年前快得多，还配有专用神经引擎，却大部分时间闲置着等 Virginia 数据中心的 JSON 响应，这很荒谬。

> "AI everywhere" 不是目标，**有用的软件**才是目标。

## 实践案例：Brutalist Report 的设备端摘要功能

作者以自己开发的 [Brutalist Report](https://brutalist.report) 为例：最近为该新闻聚合服务开发了原生 iOS 客户端，设计目标之一是确保高密度新闻阅读体验。其中有一个可选的"智能"视图，可生成文章摘要。**关键点在于：摘要完全在设备上使用 Apple 本地模型 API 生成**，无需服务器中转、无提示或用户日志、无供应商账户、无"我们保留您内容30天"的脚注。

---

## 本地 AI 的优势

### 适用场景

本地 AI **擅长**的场景：模型的工作是转换用户自有的数据，而不是充当宇宙搜索引擎。

- 总结文章（输入数据已在设备上）
- 邮件摘要
- 从笔记中提取操作项
- 文档分类

### 不适用场景

需要云端模型强大能力的情况（如复杂的推理、生成通用知识等）确实存在，但并非每个用例都需要。

## Apple 生态的工具

### 基础用法

```swift
import FoundationModels

let model = SystemLanguageModel.default
guard model.availability == .available else { return }

let session = LanguageModelSession {
  """
  Provide a brutalist, information-dense summary in Markdown format.
  - Use **bold** for key concepts.
  - Use bullet points for facts.
  - No fluff. Just facts.
  """
}

let response = try await session.respond(options: .init(maximumResponseTokens: 1_000)) {
  articleText
}

let markdown = response.content
```

### 长内容分块处理

将纯文本分块（每块约 10k 字符），每块生成简明的"纯事实"笔记，然后运行第二轮汇总成最终摘要。

### 结构化输出（新方式）

Apple 最近的改进是推动向**类型化数据**而非非结构化文本的转变：

```swift
import FoundationModels

@Generable
struct ArticleIntel {
  @Guide(description: "One sentence. No hype.") var tldr: String
  @Guide(description: "3–7 bullets. Facts only.") var bullets: [String]
  @Guide(description: "Comma-separated keywords.") var keywords: [String]
}

let session = LanguageModelSession()
let response = try await session.respond(
  to: "Extract structured notes from the article.",
  generating: ArticleIntel.self
) {
  articleText
}

let intel = response.content
```

这不仅是更好的 ergonomics，更是工程上的改进——UI 不需要从 Markdown 中提取要点或祈祷模型记住 JSON schema，直接获得具有真实字段的真实类型。

## 对"本地模型不够智能"的回应

> 正确。但那又怎样？

大多数应用功能不需要能写莎士比亚、理解量子力学并通过律师考试的模型，只需要能可靠地完成以下任务的模型：**总结、分类、提取、重写或规范化**。对于这些任务，本地模型完全可以做到出色。

- 如果你试图把本地模型当作整个互联网的替代品，你会失望
- 如果你把它当作应用内的"数据转换器"，你会好奇为什么当初要把数据发到服务器

---

## 建议

1. **只在真正必要时使用云端模型**
2. **将用户数据保留在本地**
3. **使用 AI 时不要只把它当作聊天框**，而应作为具有类型化输出和可预测行为的可靠子系统
4. 停止交付分布式系统，当你本意只是交付一个功能
