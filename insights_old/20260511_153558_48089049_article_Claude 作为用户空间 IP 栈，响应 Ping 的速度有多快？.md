## 实验背景

Adam Dunkels 进行了一个有趣的实验：让 Claude 作为用户空间 IP 栈来响应 ICMP Ping 请求。他创建了一个 `ping-respond.md` 命令，让 Claude 直接读取 TUN 设备的 IP 数据包，解析 IP 和 ICMP 头部，计算校验和，然后构造正确的 Ping 响应包并写回设备。

## 技术实现

### 工作流程

1. **读取数据包**：从 `/dev/tun0` 设备读取原始 IPv4 数据包（十六进制格式）
2. **解析 IP 头部**：解析版本、IHL、总长度、TTL、协议、源/目标 IP、校验和等字段
3. **解析 ICMP 头部**：验证 ICMP echo request (type=08)，提取标识符和序列号
4. **构造响应包**：
   - 交换源和目标 IP
   - 设置 TTL=64
   - 重新计算 IP 头部校验和
   - 将 ICMP type 从 0x08 改为 0x00 (echo reply)
   - 重新计算 ICMP 校验和
5. **写回响应**：将构造好的响应包写入 TUN 设备

### 校验和计算算法

- 将数据分成 16 位字（2 字节）
- 求和所有字（无符号整数）
- 如果和超过 0xFFFF，将进位加到低 16 位
- 取反码：result = 0xFFFF - folded_sum

## 实验结果

- **模型**：Haiku 4.5
- **往返延迟**：42592.723 毫秒（约 42.6 秒）
- **TTL**：64
- **丢包率**：0%

```
$ ping -W 300 -c 1 172.16.0.2
64 bytes from 172.16.0.2: icmp_seq=1 ttl=64 time=42593 ms
```

## 结论

这个实验展示了 LLM 能处理非常底层的网络协议栈任务。Claude 能够正确解析 IP 和 ICMP 头部，计算校验和，并生成符合 RFC 标准的响应包。虽然延迟高达 42 秒（相比之下比 RFC 1149 的实现还是快多了），但证明了"Markdown 是代码，LLM 是处理器"这一理念可以延伸到多低的层次。

这是纯粹的趣玩项目，但也有助于理解网络协议栈的工作原理以及 LLM 的推理能力边界。
