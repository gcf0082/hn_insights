# Rust 语言 LLM 使用政策 PR 洞察报告

## 基本信息

- **洞察链接**: https://github.com/rust-lang/rust-forge/pull/1040
- **PR 标题**: Add an LLM policy for `rust-lang/rust`
- **发起者**: jyn514
- **目标仓库**: rust-lang/rust-forge
- **状态**: 开放中（Open）
- **提交数**: 36 个提交

## PR 概述

该 PR 旨在为 `rust-lang/rust` 仓库制定 LLM（大型语言模型）的使用政策。该政策将被放置在 Forge 上作为一份活文档，并从 `rust-lang/rust` 的 CONTRIBUTING.md 以及 rustc-dev-guide 和 std-dev-guide 中链接引用。

## 政策范围

- **适用仓库**: `rust-lang/rust`
- **不在范围内**: subtrees、submodules、crates.io 依赖、其他 rust-lang 组织的仓库

## 主要内容

### 讨论背景

该 PR 之前在 Zulip 上进行了大量讨论，消息数超过 3000 条。鉴于讨论的广泛性，团队决定将讨论范围限制在政策本身，并明确标记某些话题为不在范围内。

### 不在范围内的话题

以下话题不允许在本 PR 中讨论：
- LLM 的长期社会或经济影响
- LLM 的环境影响
- LLM 输出的版权状态
- 对使用 LLM 的人的道德评判

### 制定动机

1. 许多人发现 LLM 生成的代码和写作令人不愉快
2. 许多人认为 LLM 是学习和发现的重要帮助
3. `rust-lang/rust` 目前面临大量低质量的 "slop" PR（主要由 LLM 生成）
4. 拥有政策可以更轻松地进行审核，而不必逐个处理每个案例

### 缺点

1. 禁止了一些有效的 LLM 使用方式（故意偏向于禁止太多而非太少）
2. 不解决道德、社会和环境影响问题
3. 不尝试设置项目范围的政策
4. 不适用于 rust-lang/rust 的 subtrees

### 替代方案考虑

1. **项目范围的政策**: 优点是统一，缺点是难以达成共识
2. **不同标准**: 对项目内部人员和外部贡献者采用不同标准
3. **更宽松的政策**: 允许"负责任和适当"的使用
4. **更严格的政策**: 完全禁止 LLM 或移除"原创性门槛"条件
5. **没有政策**: 避免禁止有效用例，但会增加审核成本

## 总结

这是一个重要的政策制定工作，旨在为 Rust 编译器仓库的 LLM 使用建立明确的指导方针。政策试图在允许 LLM 作为学习工具和防止低质量 LLM 生成内容之间取得平衡。该政策采用"原创性门槛"的方式，要求 LLM 生成的内容必须达到一定的原创性标准才能被接受。
