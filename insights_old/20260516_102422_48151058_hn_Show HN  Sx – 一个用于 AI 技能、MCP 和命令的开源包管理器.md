## 项目概述

Sx 是一个开源的 AI 技能、MCP（Model Context Protocol）和命令的包管理器。由 Sleuth 团队开发，Sx 将技能、MCP 服务器配置、斜杠命令、代理、钩子和规则文件视为版本化的软件包。用户只需定义一次，推送到 vault（本地文件夹、Git 仓库或托管后端），即可在需要的地方安装。

## 核心特性

- **版本化管理**：支持锁文件，确保安装可重现
- **作用域模型**：Org → team → repo → path → individual
- **多客户端支持**：Claude Code、Cursor、GitHub Copilot、Cline、Codex、Gemini、Kiro、claude.ai、chatgpt.com
- **跨团队共享**：解决非技术团队（如营销、法律、运营）无法使用 AI 资产的问题

## 社区讨论焦点

### 1. 命名与发音
有用户询问 Sx 的发音，开发者表示就读作 "s x"（两个字母），简短易记。

### 2. 为何不直接使用 Git？
这是讨论的热点。开发者认为：
- 仅使用 Git 存储意味着无法跨团队或组织共享
- 并非所有团队都熟悉 Git（如营销团队）
- Git 适合技术团队，但对非技术用户不友好

有用户反驳道，内部技能通常与代码库紧密耦合，适合放在 Git 中管理。外部注册的适用场景有限。

### 3. 技能依赖问题
有用户指出，许多技能相互依赖，单独安装某技能可能无法正常工作。开发者承认已考虑依赖机制，但目前实际使用率不高。

### 4. 非技术团队使用
讨论揭示了一个关键痛点：非技术用户生成内容后如何与开发团队共享。当前解决方案通常需要上传到 Google Drive，再由开发人员手动下载并推送到 Git 仓库，这对非技术用户而言门槛过高。

### 5. 工具支持
用户询问是否支持导入其他拥有独立 CLI 的工具（如 Go、Rust 编写的工具），开发者表示持开放态度。

## 总结

Sx 试图填补 AI 工具生态系统中 "npm 形状的空白"，为 AI 技能和资产提供统一的包管理方案。社区反馈主要集中在：作用域模型是否合理、技能依赖如何处理、以及如何降低非技术用户的使用门槛。该项目代表了 AI 辅助开发工具链日益成熟的发展趋势。
